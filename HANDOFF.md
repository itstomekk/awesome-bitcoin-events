## Current truth

- **README.md is the source of truth.** Upcoming events live in **one table per year** under `## Year`, with columns `| Date | Event | Location | Type |`. There are no month headings: the month lives in the Date cell, and `npm run check` rejects any `### <Month>` line with a migration hint. `PAST.md` is the archive in the same format, newest year first. `TO-VERIFY.md` holds leads without an official page; they are not on the site.
- **Website** (https://itstomekk.github.io/awesome-bitcoin-events/) is Astro. It is generated from README.md + PAST.md by `src/lib/awesome-list.js`, the single parser. The page runs masthead, then the map, then the Events/Meetups switch, then the list, then How it works. Pins come from `data/places.json`. The colour legend is an overlay in the map's top-left corner, so Leaflet's zoom control is moved to the bottom-left (`zoomControl: false` plus `L.control.zoom({ position: 'bottomleft' })`) - keep them apart. There is no masthead nav: the only call to action is the "Add event" button at the end of How it works, which opens the issue submission form. Upcoming/past status is computed in the browser. The design is an "almanac" index; all design values are tokens in `src/styles/tokens.css`.
- **Commands:** `npm run check` (validate), `npm test`, `npm run archive` (move ended events to PAST.md), `npm run dev`, and `npm run event-from-issue -- <issue-number>` (turn an "Submit an event" issue into a README row in the right year table, `--dry-run` to preview).
- **CI** (`.github/workflows/pages.yml`): check, test, awesome-lint, build, and deploy on main. awesome-lint passes cleanly since the `awesome` topic was added to the repo settings on 2026-10-02; its only output is two spell-check warnings for the lowercase `bitcoin++` series names. `links.yml` runs a weekly link check that opens an issue.
- The README carries `<!--lint disable table-pipe-alignment-->` so contributors don't have to pad table pipes. awesome-lint reports no errors; the two warnings are both the `bitcoin++` series names, which are lowercase on purpose.
- Counts on 2026-10-02: 53 upcoming (207 listed), 154 past, 4 to verify, 182 meetups, 206 places with coordinates. `npm run check` confirmed these counts.
- **Meetups** live in the `## Meetups` section of README.md, as `### <Region>` tables (one table per region: `| City, Country | [Name](link) | About |`). GitHub's tab strip is generated from recognised community files only, so the section cannot be a tab of its own - keeping it in README is what puts it on the repo's main page. The site shows them as a tab next to Events on the home page - the standalone `/meetups` page was dropped on the owner's call, since the tab is enough - rendered by `src/components/MeetupList.astro`, with blue map pins. The first batch is 45 BitDevs chapters (bitdevs.org/cities) plus 101 Meetup.com groups from BTC Map's community directory (`api.btcmap.org/v2/areas`), cleaned by hand (wrong or shared links dropped, place names fixed). A second batch of 11 rows came from the NIP-52 scan on 2026-10-02, and a third batch added the BitcoinWalk weekly walk from its per-city pages - trimmed on the owner's call to the 29 cities we already cover (15% of the file), because importing all 126 cities let one movement dominate the list.
- **NIP-52 calendars (Plektos and Satlantis) - sources for a re-scan.** Both apps are front ends over the same NIP-52 event kinds on relays, so one scan covers both. Query kinds `31922` (date-based) and `31923` (time-based), dedupe by `(pubkey, kind, d)` keeping the newest `created_at` (they are addressable events), and read `title`, `start`/`end`, `location`, `start_tzid`, `client`, the `r` link and the content. Plektos uses `wss://relay.ditto.pub`, `wss://relay.dreamith.to` and `wss://jskitty.com/nostr` (taken from its JS bundle); Satlantis uses `wss://relay.satlantis.io`. For coverage add `wss://nostr.mom`, `wss://nos.lol` and `wss://relay.primal.net`; `relay.damus.io` answered 503, `nostr.wine` 403, `purplepag.es` caps `limit` at 500 and `relay.fountain.fm` rejects these kinds outright. The 2026-10-02 run returned 3,255 raw events, 2,193 unique, 493 future and 394 absent from this repo - but 239 of those came from a single publisher (Club Orange, formerly Orange Pill App), which mostly mirrors cities already listed, so check the publisher before reading volume as coverage. `location` is free text and usually a venue plus a street address, so group by publisher rather than by city. Expect recurring local meetups, not conferences.
- **BitcoinWalk** (`bitcoinwalk.org`) is a recurring weekly walking-meetup series with one page per city; its sitemap (`https://bitcoinwalk.org/bitcoin_walk-sitemap.xml`) lists them all, and the page `<title>` gives the city ("Köln - BitcoinWalk", "BitcoinWalk in Migori"). Country and coordinates come from Nominatim. It is a single movement, not one organiser per city, so a scan of it returns ~120 cities at once - check whether the volume is wanted before adding another batch.
- **Conference directories worth re-scanning (checked 2026-10-02).** Most of these are plain tables, so a re-scan is a fetch plus a diff against README.md, not a browser job:
  - `proofofconference.com` renders from a **public CSV on GitHub**: `raw.githubusercontent.com/goldisdying/proofofconference/main/Bitcoin%20Conference%20List%20-%20Directory.csv` (177 rows; columns Conference / Date Range / City / State / Country / Venue / Discount / Main Conference Link / Not Active). The best of the six - dates, venues, links and discount codes in one file. Ignore rows whose "2027" edition still carries a 2026 date: the maintainer copies last year's row forward before the next edition is announced, and those dates are placeholders.
  - `bitvocation.com/bitcoin-conferences-discounts` - one table (name, region, city, dates, discount code, ticket link).
  - `braiins.com/blog/the-best-bitcoin-conferences-events-of-2026` - a 2026 guide with a "Braiins attending" column. The only source that also lists mining and energy events (DTECH, ERCOT, NAPE, TEMS, Wall Street Bets, Consensus), which are mostly not Bitcoin-only - filter before adding.
  - `bitbo.io/tools/conferences/` - four Bitcoin-only conferences, three without dates.
  - `btceventsmap.com` is a **Bubble app**: its public data API (`/api/1.1/obj/events`) exposes only a test table, so read the rendered page instead (`agent-browser open https://btceventsmap.com`, then parse the card text as date / city / name / type). Its 24 conferences are all already listed.
  - The Airtable share link that circulated in October 2026 is dead ("This private share link is no longer available").
- What those sources gave us on 2026-10-02: Bitcoin for Financial Services Summit 2026 (Oct 20-22, Denver), Max & Stacy Bitcoin Golf Invitational 2027 (Jan 11-13, El Encanto), Heatpunk Summit 2027 (Feb 26-27, Denver) and TGFB27 (Jul 15, 2027, Nashville). Golden Gate Bitcoin Conference (Nov 6-7, Kentfield) looked like a find and turned out to be **cancelled for 2026** - always open the organiser's page before adding anything a directory lists.
- **Aggregators are research only, never published (owner's call, 2026-10-02).** Calendars and clients (`app.cluborange.org`, `armada.buzz`, Lu.ma event pages, `njump.me`, `bitcoinonly.events`, ...) are how we *find* events; the link in a published row must still be the organiser's own page, as `.github/CONTRIBUTING.md` requires. An event we know only from an aggregator goes to `TO-VERIFY.md` with the calendar link in its "Spotted on" column - that is where the Grand Rapids Drury Inn Meetup Weekend (Nov 6-8, Michigan) sits.
- **Event details:** clicking a row expands it to show the full dates with weekday, a countdown, add-to-calendar (.ics / Google), show on map, copy link (`#event-id` deep links) and report-a-correction. Optional descriptions and images come from `data/details.json`, keyed by official URL and filled by `npm run enrich` (the organizer's og:description / og:image). Always review the result; hand-fixed entries use `"source": "manual"`.
